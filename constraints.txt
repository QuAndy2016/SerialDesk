# Build-time version pins (2026-10-03, ).
#
# Why: the CI workflow installed PySide6/pyserial from loose ">=" ranges in
# requirements.txt and installed the newest pyinstaller, so the same commit could produce
# a different bundle on a different day. These pins make the CI build and a local build
# install the same versions.
#
# Scope: pip's own semantics for a constraints file are that it "only controls which
# version of a requirement is installed, not whether it is installed" - listing a package
# here does NOT install it (pip user guide, "Constraints Files"). requirements.txt keeps
# its loose ranges on purpose, so running from source is unaffected; only the builds that
# pass -c constraints.txt are pinned.
#
# Values: what PyPI resolves as newest today and what this machine verified
# (metadata checked 2026-10-03: PySide6 6.11.2 requires >=3.10,<3.15; pyinstaller 6.22.3
# requires >=3.8,<3.16; pyserial 3.5). Both the CI runner (Python 3.12) and this machine
# (Python 3.14) are inside those windows, so one pin set covers both.
PySide6==6.11.2
pyserial==3.5
pyinstaller==6.22.3
